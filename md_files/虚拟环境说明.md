# 虚拟环境 - Python 开发标准做法

## 为什么使用虚拟环境？

虚拟环境是 Python 开发的标准做法，所有专业 Python 项目都使用虚拟环境。这不是可选项，而是行业标准。

## 核心区别

### 系统安装（不推荐，非标准做法）
```bash
pip install -r requirements.txt  # 不推荐
```
- **安装位置**: 直接安装到系统的 Python 环境中
- **影响范围**: 所有 Python 项目共享这些包
- **权限要求**: 可能需要 `sudo`（Linux/macOS）
- **隔离性**: 无隔离，不同项目的依赖可能冲突
- **问题**: 违反 Python 开发标准，会导致依赖冲突

### 虚拟环境安装（标准做法）⭐
```bash
python -m venv venv
source venv/bin/activate  # macOS/Linux
# 或
venv\Scripts\activate     # Windows
pip install -r requirements.txt
```
- **安装位置**: 安装到项目目录下的独立环境
- **影响范围**: 只影响当前项目
- **权限要求**: 不需要管理员权限
- **隔离性**: 完全隔离，不同项目互不影响
- **标准**: 这是 Python 开发的标准做法，所有专业项目都这样做

## 详细对比表

| 特性 | 系统安装 | 虚拟环境安装 |
|------|---------|------------|
| **依赖隔离** | ❌ 所有项目共享 | ✅ 每个项目独立 |
| **版本冲突** | ⚠️ 容易发生 | ✅ 避免冲突 |
| **权限要求** | ⚠️ 可能需要 sudo | ✅ 不需要 |
| **项目可移植性** | ❌ 依赖系统环境 | ✅ 可打包环境 |
| **磁盘占用** | 较小（共享） | 较大（每个项目一份） |
| **适用场景** | 系统工具、全局工具 | 开发项目、多项目 |

## 实际例子

### 场景1: 多个项目需要不同版本的 pandas

**系统安装（有问题）**:
```bash
# 项目A 需要 pandas 1.5.0
pip install pandas==1.5.0

# 项目B 需要 pandas 2.0.0
pip install pandas==2.0.0  # 会覆盖 1.5.0，项目A可能出错
```

**虚拟环境（正确）**:
```bash
# 项目A
python -m venv venv_a
source venv_a/bin/activate
pip install pandas==1.5.0  # 只在项目A中

# 项目B
python -m venv venv_b
source venv_b/bin/activate
pip install pandas==2.0.0  # 只在项目B中，互不影响
```

### 场景2: 系统 Python 被污染

**系统安装（风险）**:
```bash
# 安装某个包时可能破坏系统 Python
sudo pip install some-package  # 可能影响系统其他程序
```

**虚拟环境（安全）**:
```bash
# 即使出错也只影响当前项目
pip install some-package  # 不会影响系统
```

## 什么时候用虚拟环境？

### ✅ 必须使用虚拟环境的情况

1. **所有 Python 项目** - 这是标准做法
2. **开发项目** - 所有开发项目都必须用
3. **多项目开发** - 同时维护多个项目
4. **依赖复杂** - 项目有很多依赖包
5. **团队协作** - 需要统一环境
6. **生产部署** - 需要精确控制依赖版本

### 特殊情况

1. **系统工具** - 全局安装的命令行工具（很少见）
2. **Docker 容器** - 容器本身已提供隔离（但容器内仍建议用虚拟环境）

> **重要**: 即使是单项目，也应该使用虚拟环境。这是 Python 开发的标准做法，不是可选项。

## 虚拟环境完整使用流程

### 1. 创建虚拟环境

```bash
# 在项目目录下
python -m venv venv

# 或指定 Python 版本
python3.10 -m venv venv
```

### 2. 激活虚拟环境

**macOS/Linux**:
```bash
source venv/bin/activate
```

**Windows**:
```cmd
venv\Scripts\activate
```

激活后，命令行提示符会显示 `(venv)`:
```bash
(venv) user@computer:~/project$
```

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

### 4. 使用项目

```bash
python app.py
# 所有操作都在虚拟环境中
```

### 5. 退出虚拟环境

```bash
deactivate
```

## 虚拟环境管理技巧

### 查看已安装的包

```bash
pip list
```

### 导出依赖列表

```bash
pip freeze > requirements.txt
```

### 删除虚拟环境

```bash
# 先退出
deactivate

# 删除目录
rm -rf venv  # macOS/Linux
rmdir /s venv  # Windows
```

### 使用 conda（替代方案）

```bash
# 创建环境
conda create -n excel_agent python=3.10

# 激活
conda activate excel_agent

# 安装依赖
pip install -r requirements.txt
```

## 常见问题

### Q: 虚拟环境会占用很多空间吗？
A: 每个虚拟环境大约占用 50-200MB，对于现代硬盘来说很小。

### Q: 可以共享虚拟环境吗？
A: 不推荐。每个开发者应该创建自己的虚拟环境，但可以共享 `requirements.txt`。

### Q: 虚拟环境需要提交到 Git 吗？
A: **不需要**！应该在 `.gitignore` 中添加 `venv/`。

### Q: 如何在不同机器上使用相同的环境？
A: 使用 `requirements.txt`:
```bash
# 机器A: 导出
pip freeze > requirements.txt

# 机器B: 安装
pip install -r requirements.txt
```

## 最佳实践（Python 开发标准）

1. ✅ **总是使用虚拟环境** - 这是 Python 开发的标准做法，不是可选项
2. ✅ **提交 `requirements.txt`** - 到版本控制系统
3. ✅ **不要提交 `venv/`** - 目录已在 `.gitignore` 中
4. ✅ **在 README 中说明** - 如何设置虚拟环境
5. ✅ **使用 `python -m venv`** - Python 3.3+ 内置，不需要额外安装

> **说明**: 这些不是"推荐做法"，而是 Python 开发的标准做法。所有专业 Python 项目都遵循这些规范。
